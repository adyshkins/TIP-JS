## О дисциплине

Курс посвящён последовательной разработке веб-приложения: от первых программ на JavaScript до взаимодействия клиента, сервера и базы данных. Помимо написания кода, в задания входят работа с Git, проверка входных данных, отладка, тестирование и документирование запуска.

**Цель курса** — освоить базовый цикл разработки учебного фулстек-приложения и научиться объяснять, как его части работают вместе.

К завершению курса студент должен уметь:

- писать и отлаживать JavaScript-код, выделять функции и модули;
- создавать интерактивный интерфейс средствами браузера и React;
- выполнять асинхронные запросы и обрабатывать состояния загрузки и ошибки;
- разрабатывать HTTP API на Node.js и Express, проверять данные на сервере;
- проектировать небольшую реляционную базу данных и подключать её к приложению;
- проверять код, вести историю изменений и оформлять воспроизводимый запуск.

**Предварительная подготовка:** базовые представления о переменных, условиях и циклах. Для последующих работ понадобятся основы HTML и CSS. В ПР1 HTML-шаблон предоставляется; предварительное знание JavaScript не требуется.

README описывает учебные материалы и не заменяет утверждённую рабочую программу дисциплины. Календарные сроки, форма итогового контроля и официальная система оценивания здесь не устанавливаются.

## С чего начать

1. Откройте [методичку ПР1](./practices/practice-01/README.md) и выполните предварительную подготовку. Версии инструментов и способы запуска указаны в самой работе.
2. Создайте **собственный репозиторий с решениями** по инструкции ПР1. Этот репозиторий курса предназначен для методичек, а не для размещения студенческих отчётов.
3. Выполните задания, проверьте результаты, оформите отчёт и подготовьтесь объяснить своё решение.

Для ПР1 достаточно редактора, браузера, Node.js, npm и Git. React, Express и PostgreSQL подключаются на соответствующих этапах курса, а не устанавливаются заранее.

[Стартовые файлы ПР1](./practices/practice-01/starter/) можно использовать вместо ручного создания файлов. Копируйте **содержимое** этой папки в корень своего учебного репозитория, не создавая дополнительную папку `starter`. Не перезаписывайте существующие README и `.gitignore` без просмотра. Заготовки не являются готовыми решениями: часть файлов нужно дополнить, а в задании по отладке намеренно оставлены ошибки.

## Сквозной проект

Основной учебный пример — **система управления задачами**. В обязательный объём итогового приложения входят задачи и категории, создание и редактирование записей, изменение статуса, поиск и фильтрация.

Проект развивается по этапам:

```text
Расчётные программы на JavaScript
    → функции, модель данных и модули
    → интерфейс на DOM и локальное хранение
    → работа с учебным API
    → перенос интерфейса на React
    → собственный сервер на Express
    → хранение данных в PostgreSQL
    → тестирование и итоговый релиз
```

В ПР5–ПР8 по плану используется подготовленный преподавателем учебный API. В ПР9–ПР10 студенты реализуют собственный сервер с тем же контрактом. Комплект учебного API будет приложен к соответствующим методичкам; в текущей версии материалов его ещё нет.

На первых занятиях выполняются отдельные учебные задания. Затем ранее разработанные функции и модель данных используются в приложении. При переходе на React изменяется слой интерфейса, а не вся работа начинается заново.

По согласованию с преподавателем допускается другая предметная область: каталог книг, учёт оборудования или обработка заявок. Технический минимум и сопоставимая сложность сохраняются: две связанные сущности, операции с данными, валидация, API, база данных и проверки.

**Граница обязательного объёма:** учебное приложение с тестовыми данными и воспроизводимым запуском. TypeScript, Redux, Next.js, микросервисы, Kubernetes, полноценная регистрация пользователей и разграничение доступа не входят в обязательный минимум этого плана. Обзор CI и контейнеризации не означает требование самостоятельно освоить всю инфраструктуру развёртывания.

## Организация работы

На лекциях разбираются понятия, устройство технологий и типичные ошибки. На практиках выполняются ключевые этапы реализации и проверки. Подготовка окружения, завершение индивидуального варианта и оформление результатов выполняются самостоятельно в объёме, указанном в методичке.

Каждая практическая работа выполняется индивидуально, если в её задании прямо не указан другой формат. Основное внимание уделяется работоспособности, понятности решения и проверкам, а не количеству кода или дополнительных библиотек.

Для фиксации этапов используйте содержательные Git-коммиты. Не требуется механически копировать всё приложение в четырнадцать папок: расположение исходного кода определяется методичками, а отчёт фиксирует результат конкретного этапа. На поздних этапах полезно указывать в отчёте коммит, соответствующий сдаваемой версии.

## Порядок сдачи

Сдаётся ссылка на соответствующую работу **в личном репозитории студента**. Например, для ПР1 — на папку `practice-01`, а не на методичку в репозитории курса. Если репозиторий закрытый, преподавателю должен быть предоставлен доступ.

Перед сдачей необходимо:

- разместить исходный код и инструкцию запуска с указанием рабочей папки и необходимых настроек;
- выполнить обязательные проверки и записать фактические результаты, включая граничные и ошибочные случаи;
- оформить отчёт в README работы, указав автора, группу, вариант, выполненные задания и выводы;
- проверить доступность файлов по ссылке и подготовиться запустить, объяснить и изменить код на защите.

Отчёт не должен дублировать все исходные файлы. Скриншоты не заменяют код и текстовые результаты проверок. Ожидаемые и фактически полученные результаты указываются отдельно. Пароли, токены и реальные персональные данные в учебный репозиторий не включаются.

Для ПР1 отчёт размещается в `practice-01/README.md`; отдельный документ Word или PDF не требуется. Особенности сдачи следующих работ будут указаны в их методичках.

### Принципы оценивания

Проверяются выполнение обязательного задания и своего варианта, корректность на разных данных, качество оформления и понимание решения. Установка дополнительных библиотек, декоративная вёрстка и объём кода сами по себе не повышают оценку.

Конкретные критерии приведены в методичке каждой работы. Шкала ПР1 является рекомендуемой и не заменяет утверждённую систему оценивания дисциплины. **Оценка «отлично» предполагает успешную защиту**, а не только наличие файлов в репозитории.

Документация и вспомогательные инструменты могут использоваться для обучения. Студент должен понимать, проверять и уметь изменять представленный код; наличие сгенерированного или скопированного решения само по себе не подтверждает освоение материала.

**Не путайте два назначения README:**

| Место | Что хранится |
|---|---|
| Корень репозитория курса | Описание дисциплины, план и ссылки на учебные материалы. |
| `practices/practice-01/README.md` в репозитории курса | Задание преподавателя и методические указания. |
| Корень личного репозитория студента | Автор и навигация по выполненным работам. |
| `practice-01/README.md` в личном репозитории студента | Отчёт, команды запуска и результаты выполнения ПР1. |

Относительные ссылки рассчитаны на указанное расположение папок. При добавлении материалов сохраняйте пути `lectures/lecture-XX/README.md` и `practices/practice-XX/README.md`, заменяйте страницы-планы полноценными материалами и обновляйте статусы в этом файле.
