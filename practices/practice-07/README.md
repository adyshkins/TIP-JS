> В ПР6 интерфейс строился через DOM и обращался к учебному серверу. В ПР7 та же предметная модель переносится в React. Чтобы отдельно освоить компоненты и состояние, используется локальный набор данных. Подключение React-приложения к API относится к ПР8. Реализованные HTTP-модули ПР5–ПР6 сохраняются для следующего этапа.

## 1. Цель и результат работы

**Цель** — освоить построение интерфейса из функциональных компонентов и управление данными через состояние React.

В результате выполнения необходимо получить приложение, которое:

- отображает задачи и названия категорий;
- создаёт и редактирует задачи с проверкой полей;
- переключает статус и удаляет задачи после подтверждения;
- совместно применяет поиск и фильтры статуса, приоритета и категории;
- показывает общую статистику и число найденных записей;
- выводит понятное сообщение при пустой выборке;
- сохраняет согласованность списка, формы и статистики после каждого действия;
- проходит проверки предметных функций и сборку, а также ручные сценарии интерфейса.

Данные находятся в памяти текущей страницы. Перезагрузка восстанавливает исходный набор. Это ожидаемое поведение ПР7, которое необходимо объяснить в отчёте.

## 4. Модель данных и границы контрактов

Схема задачи сохраняется из ПР6:

```js
{
  id: 4,
  title: 'Подготовить модель задач',
  completed: false,
  priority: 'high',
  categoryId: 2
}
```

Категория имеет вид `{ id: 2, name: 'Проект' }`. В наборе 12 задач и три категории. Идентификаторы задач идут с пропусками: индекс массива не равен `id`.

Черновик формы содержит `title`, `priority`, `categoryId`. Значение HTML-поля категории является строкой; при валидации оно преобразуется в число. Допустимы приоритеты `low`, `medium`, `high`. Название после `trim` должно содержать от 1 до 100 единиц длины JavaScript-строки (`length`), категория должна существовать в справочнике.

Фильтры хранят значения, удобные для управляемых HTML-полей:

```js
{ q: '', completed: '', priority: '', categoryId: '' }
```

Пустая строка отключает соответствующий фильтр. `completed` принимает `''`, `'true'` или `'false'`; `categoryId` — `''` либо строку существующего id. Поиск выполняется по `title`, без учёта регистра и крайних пробелов. Все непустые фильтры объединяются условием **И**. Порядок задач сохраняется.

Важно: `Boolean('false')` равно `true`. Для фильтра статуса требуется явное сравнение со строкой `'true'` или `'false'`.

## 5. Теоретические сведения

### 5.1. Компонент, JSX и props

Компонент — функция с именем с заглавной буквы, возвращающая JSX. JSX описывает нужное представление данных; это не строка HTML. Используются `className`, `htmlFor`, закрытые теги и выражения внутри `{}`.

```jsx
function Greeting({ name }) {
  return <p>Здравствуйте, {name}!</p>;
}
```

В `<Greeting name="Сергей" />` родитель передаёт значение через props. Дочерний компонент не изменяет полученные props. Для пользовательского текста применяется обычная вставка `{task.title}`; `dangerouslySetInnerHTML` для названий не используется.

Основы JSX, событий и props разобраны в [React: Quick Start](https://react.dev/learn).

### 5.2. Состояние и обработчики

Локальная переменная не сохраняет состояние между вызовами компонента. `useState` предоставляет текущее значение и функцию запроса обновления. Если новое значение зависит от предыдущего, используется функциональное обновление:

```jsx
const [count, setCount] = useState(0);
const increment = () => setCount(previous => previous + 1);
return <button onClick={increment}>{count}</button>;
```

Обработчик передаётся, а не вызывается при рендере: `onClick={increment}`, не `onClick={increment()}`. Хуки вызываются на верхнем уровне компонента, а не внутри условия или обработчика.

В заготовке включён `StrictMode`. В режиме разработки React может повторно вызывать функции, которые должны быть чистыми. Поэтому изменение счётчика id, `confirm` и другие побочные действия не размещаются внутри функции обновления состояния. Подробнее: [React: StrictMode](https://react.dev/reference/react/StrictMode).

### 5.3. Неизменяемые обновления

Для изменения массива создаётся новый массив, для изменения записи — новый объект. `map` подходит для замены, `filter` — для удаления, `[...previous, item]` — для добавления. Например, при изменении объекта недостаточно скопировать только массив и затем присвоить `next[0].completed = true`: ссылка на сам объект могла остаться общей.

Предметные функции этой работы не изменяют входные данные. Исходный набор заморожен, чтобы случайные мутации обнаруживались раньше. См. [React: Updating Arrays in State](https://react.dev/learn/updating-arrays-in-state).

### 5.4. Владелец состояния и вычисляемые значения

`App` хранит `tasks`, `filters` и `editingId`. Компонент формы хранит черновик и ошибки полей. Категории импортируются как справочник.

Из `tasks` и `filters` на каждом рендере вычисляется видимая выборка. Из всего `tasks` вычисляется статистика; выбранная запись находится по `editingId`. Отдельные состояния для этих результатов не создаются: иначе их пришлось бы синхронизировать после каждого действия. Такой подход разобран в [React: Choosing the State Structure](https://react.dev/learn/choosing-the-state-structure).

Данные передаются вниз через props. Действия сообщаются наверх через функции: карточка вызывает, например, `onToggle(task.id)`, а `App` изменяет общий массив.

### 5.5. Списки и ключи

При создании компонентов через `map` ключ задаётся на непосредственном элементе массива:

```jsx
items.map(item => <Item key={item.id} item={item} />)
```

Для изменяемого списка нельзя использовать индекс или случайное значение. Стабильный id связывает элемент с его состоянием при удалении и перестановке. `key` служит React и не передаётся компоненту как обычный prop. См. [React: Rendering Lists](https://react.dev/learn/rendering-lists).

### 5.6. Управляемая форма

Управляемое поле получает `value` из состояния и обновляет его через `onChange`. В начальном состоянии текстового поля используется строка, а не `undefined`. Для checkbox применяются `checked` и `event.target.checked`.

При отправке формы вызывается `event.preventDefault()`. Кнопки отмены, удаления и переключения получают `type="button"`; кнопка сохранения — `type="submit"`. У полей должны быть связанные `label` и `id`. См. [React: input](https://react.dev/reference/react-dom/components/input).

### 5.7. Переключение редактируемой записи

Начальное значение `useState(initialTask)` используется при монтировании, а не при каждом обновлении props. Для этой работы предлагается пересоздавать форму при переходе к другой задаче:

```jsx
<TaskForm key={editingId ?? 'new'} initialTask={editingTask} /* остальные props */ />
```

При смене ключа локальное состояние формы сбрасывается. После успешного создания черновик очищается самой формой; после успешного редактирования `App` возвращает `editingId` в `null`. При ошибке введённые данные сохраняются. Подробнее: [React: Preserving and Resetting State](https://react.dev/learn/preserving-and-resetting-state).

## 6. Контракты функций и компонентов

### 6.1. Предметные функции

Файл `src/domain/task-service.js` не импортирует React, не обращается к DOM и сети.

| Функция | Контракт |
|---|---|
| `validateTaskDraft(draft, categories)` | Возвращает `{ valid, value, errors }`. `value` содержит нормализованные `title`, `priority`, числовой `categoryId`. `errors` содержит непустые сообщения по ключам неверных полей. При успехе `errors = {}`. |
| `selectTasks(tasks, filters)` | Возвращает массив подходящих задач в исходном порядке. |
| `getTaskStats(tasks)` | Возвращает `{ total, completed, active }`. Для пустого набора все значения равны 0. |
| `addTask(tasks, value, id)` | Возвращает новый массив с задачей в конце; `completed: false`. Неположительный, нецелый или уже занятый числовой id отклоняется через исключение. |
| `updateTask(tasks, id, value)` | Заменяет только `title`, `priority`, `categoryId` найденной записи, сохраняя `id` и `completed`. |
| `toggleTask(tasks, id)` | Инвертирует `completed` выбранной записи. |
| `removeTask(tasks, id)` | Удаляет запись по id. |

`draft` — объект из полей формы; отсутствующее или нестроковое название считается ошибкой. Необходимо вернуть ошибки всех неверных полей сразу. `value` при `valid: false` не используется и не сохраняется. Преобразование категории не должно принимать `'2x'` как число 2: `parseInt` для такой проверки недостаточен.

Функции изменения получают **уже проверенный** `value`; проверка формы выполняется до их вызова. Массив задач, справочник и фильтры соответствуют описанным схемам — универсальный парсер произвольных внешних JSON в ПР7 не требуется.

Для неизвестного id редактирование, переключение и удаление сохраняют содержимое набора без исключения. Возврат той же ссылки в этом случае разрешён. При фактическом изменении возвращается новый массив. Ни одна функция не изменяет аргументы.

### 6.2. Компоненты

| Компонент | Входные данные и действия |
|---|---|
| `TaskStats` | `stats`: показывает всего, выполнено, в работе по полному набору. |
| `TaskFilters` | `filters`, `categories`, `onChange(nextFilters)`: четыре управляемых поля и кнопка сброса всех фильтров. |
| `TaskList` | `tasks` — уже отфильтрованные записи, `categories`, `onToggle(id)`, `onEdit(id)`, `onDelete(id)`. Выводит количество найденных и `TaskItem`, либо пустое состояние. |
| `TaskItem` | `task`, `categoryName` и три обратных вызова. Показывает название, статус, приоритет, категорию и действия. |
| `TaskForm` | `categories`, `initialTask` или `null`, `onSave(value)`, `onCancel()`. Хранит черновик и ошибки, проверяет ввод, затем вызывает `onSave`. |

`onSave(value)` в этой работе синхронный, возвращает `true` при принятом изменении и `false`, если сохранение не состоялось. Форма очищается только при `true`. При `false` показывается сообщение и сохраняется черновик. Если редактируемая задача уже отсутствует, `App` возвращает `false`. Этот контракт предстоит адаптировать к Promise в ПР8.

## 7. Порядок выполнения

### Шаг 1. Запустить и изучить заготовку

Проверить начальную страницу и запуск `examples/Counter.jsx`: временно импортировать компонент в `App`, вывести два счётчика с разными `step` и убедиться в независимости их состояния. После изучения убрать пример с основной страницы.

### Шаг 2. Реализовать чистые функции

Адаптировать проверку формы из предыдущих работ, затем реализовать фильтры, статистику и операции изменения. Запустить `npm test`, разбирать первое содержательное сообщение ошибки. Для массивов использовать идентификаторы, а не позиции.

### Шаг 3. Собрать карточки и список

Реализовать `TaskItem` и `TaskList`, временно передав полный массив. Приоритеты отобразить понятными названиями: «Низкий», «Средний», «Высокий». Статус — «В работе» или «Выполнена». Название категории искать по `categoryId`. Ключ карточки — `task.id`.

Карточка не хранит отдельную копию задачи в собственном состоянии. При изменении props она отображает актуальные данные родителя.

### Шаг 4. Подключить переключение и удаление

В `App` реализовать обработчики с функциональным обновлением массива. Подтверждение удаления выполняется **перед** вызовом `setTasks`; при отказе ничего не меняется. При удалении редактируемой записи дополнительно сбрасывается `editingId`.

Обработчики передать в список и далее в карточки. DOM не изменять через `querySelector`, `innerHTML` или `append`: интерфейс определяется JSX и состоянием.

### Шаг 5. Создать форму

Черновик создания: пустое название, приоритет `medium`, первая категория из справочника. Для редактирования черновик заполняется выбранной задачей, категория переводится в строку для поля `select`.

Добавить название, приоритет, категорию, сохранение и отмену. У формы использовать `noValidate`, чтобы ручные сценарии проверяли собственные сообщения валидации. Ограничение 100 символов проверять в JavaScript; `maxLength` не должен мешать проверке ввода 101 символа.

При отправке:

1. предотвратить стандартную отправку;
2. вызвать `validateTaskDraft`;
3. записать ошибки всех полей;
4. при ошибке сохранить значения и не вызывать `onSave`;
5. при успехе передать нормализованный `value` в `onSave`;
6. очистить черновик только после успешного сохранения.

Ошибки связать с полями через `aria-describedby`, неверным полям задать `aria-invalid`. Сообщение о результате выводить в области `role="status"`, ошибки сохранения — `role="alert"`.

### Шаг 6. Подключить создание и редактирование

Для учебных локальных id допускается вычислять следующий id как максимум **полного** массива плюс 1; для пустого массива — 1. Вычисление выполняется внутри чистого обновления на основе `previous`. Не использовать длину массива и максимум видимой выборки. Повторное использование удалённого максимального id в этой работе допустимо: требуется уникальность среди текущих записей.

При редактировании `App` хранит id, а саму задачу находит в актуальном массиве. Переход между задачами сбрасывает форму с помощью `key`, как показано в разделе 5.7. Отмена не изменяет массив. Успешное редактирование сохраняет статус задачи и возвращает форму в режим создания.

### Шаг 7. Подключить фильтры и статистику

Вычислить `visibleTasks = selectTasks(tasks, filters)` и `stats = getTaskStats(tasks)`. Использовать их непосредственно при рендере, без дополнительного `useState` и `useEffect`.

Сброс фильтров устанавливает четыре пустые строки; он не восстанавливает начальный фильтр варианта и не удаляет задачи. Изменение фильтров не отменяет редактирование: форма может продолжать показывать задачу, скрытую выборкой.

После создания неподходящей под фильтры задачи общий счётчик увеличивается, но карточка не появляется. После смены статуса задача может исчезнуть из текущей выборки. Это корректное поведение; сообщение об успешном действии позволяет отличить его от ошибки.

## 10. Типичные ошибки

| Проявление | Причина и способ проверки |
|---|---|
| Экран не обновляется | Изменён существующий массив или объект; проверить возврат новых значений. |
| Кнопка срабатывает при рендере | Обработчик вызван в JSX вместо передачи функции. |
| Фильтр «В работе» показывает выполненные | Использован `Boolean('false')`; требуется явное сравнение. |
| Дублируются id | Взята длина массива или максимум отфильтрованного списка. |
| При редактировании изменяется статус | Запись заменена целиком без сохранения `completed`. |
| Форма показывает прежнюю задачу | Ожидается повторное применение начального значения `useState`; проверить `key`. |
| После удаления редактирование осталось | Не сброшен `editingId` в обработчике удаления. |
| Статистика расходится со списком | В состоянии дублируются производные данные или статистика считается по выборке. |
| После отправки обновляется страница | Нет `preventDefault` или неверный тип кнопки. |
| Возникает предупреждение про `value` | Начальное значение поля равно `undefined` либо отсутствует `onChange`. |
| `npm ci` сообщает об отсутствии lock-файла | Проверить перенос `package-lock.json` из заготовки и текущую рабочую папку. |
| JSX не открывается напрямую | Приложение запущено через `file://`, а не Vite. |
