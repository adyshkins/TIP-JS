# Практическая работа № 1

**Тема: Подготовка окружения и первые программы на JavaScript**

**Дисциплина:** Технологии индустриального программирования  
**Направление подготовки в рамках курса:** фулстек-разработка  
**Форма выполнения:** индивидуальная  
**Результат:** Git-репозиторий с исходным кодом, инструкцией запуска и результатами проверок  
> В этой работе мы ещё не создаём полноценный интерфейс приложения. Учимся запускать JavaScript, понимать типы данных, писать условия и циклы, проверять результаты и находить ошибки. Вывод выполняется в консоль. Функции, объекты, массивы и модули станут основой следующей практической работы.

## 1. Цель и задачи работы

**Цель работы** — подготовить рабочее окружение и освоить базовый цикл разработки программы на JavaScript: написать код, запустить его, проверить результат, исправить ошибку и сохранить изменения в Git.

После выполнения работы необходимо уметь:

1. Запускать JavaScript в браузере и через Node.js, различать эти среды выполнения.
2. Использовать `const`, `let`, основные типы данных, явное преобразование типов, условия и циклы.
3. Проверять обычные, граничные и некорректные входные данные.
4. Применять консоль и точки останова в инструментах разработчика браузера.
5. Организовывать файлы работы в Git-репозитории и оформлять воспроизводимую инструкцию запуска.

## 2. Организация работы

## 4. Теоретические сведения

### 4.1. Язык и среда выполнения

**JavaScript** — язык, на котором написана программа. **Браузер** и **Node.js** — среды, которые могут её выполнить.

Браузер предоставляет средства работы со страницей, в частности объект `document`. Обычный запуск файла через Node.js не создаёт HTML-страницу и не предоставляет браузерный DOM. Поэтому не любой код для браузера можно без изменений запустить в Node.js. Источники: [JavaScript и браузерные API][js-intro], [различия Node.js и браузера][node-browser].

```js
console.log("Программа запущена");
console.log("Тип document:", typeof document);
```

Первая строка выводит сообщение. Вторая позволяет сравнить окружения: в обычной вкладке браузера ожидается `object`, при обычном запуске в Node.js — `undefined`.

`console.log()` выводит результат в консоль, но сам по себе не добавляет текст на HTML-страницу. В этой работе это основной способ наблюдать результат программы.

### 4.2. Переменные, `const` и `let`

```js
const courseName = "Технологии индустриального программирования";
let completedCount = 0;

completedCount = completedCount + 1;

console.log(courseName);
console.log(completedCount);
```

`const` запрещает повторное присваивание переменной. `let` допускает присваивание нового значения. Оба объявления имеют блочную область видимости. В наших решениях используйте `const`, когда повторное присваивание не нужно, и `let` — для изменяемого значения, например счётчика.

Запрет переприсваивания через `const` не означает, что объект, на который ссылается переменная, автоматически становится неизменяемым. Объекты подробнее рассмотрим в ПР2. Источник: [объявления переменных и типы][js-basics].

Имена должны отражать смысл: `completedTasks`, `dailyLimit`, `remainingTasks`. В рамках курса используем английские имена в стиле `camelCase`.

### 4.3. Типы данных

В этой работе основное внимание уделяется следующим значениям:

| Тип | Пример | Назначение |
|---|---|---|
| `number` | `12`, `3.5` | Числа. |
| `string` | `"Учебный проект"`, `"12"` | Текст, в том числе текстовая запись числа. |
| `boolean` | `true`, `false` | Логические значения. |
| `undefined` | Значение переменной после `let result;` | Значение ещё не присвоено. |
| `null` | `null` | Явно заданное отсутствие значения. |

Это не полный перечень типов JavaScript. Также существуют `bigint`, `symbol` и `object`. Полный перечень приведён в [документации MDN][js-basics].

Оператор `typeof` помогает исследовать тип значения:

```js
const firstValue = 12;
const secondValue = "12";

console.log(typeof firstValue);  // number
console.log(typeof secondValue); // string
```

Особые случаи: `typeof null` возвращает `"object"`, хотя `null` — отдельное примитивное значение; `typeof NaN` возвращает `"number"`. Поэтому одного `typeof` недостаточно для проверки допустимости числовых данных. Источники: [typeof][js-typeof], [Number][js-number].

### 4.4. Преобразование типов и сравнение

Для исходных строк оператор `+` выполняет конкатенацию — объединение текста:

```js
const firstText = "14";
const secondText = "6";

console.log(firstText + secondText);                 // 146
console.log(Number(firstText) + Number(secondText)); // 20
```

`Number()` преобразует значение в число. Непреобразуемая строка даёт `NaN`, но пустая строка и строка из пробелов дают `0`. Поэтому преобразование и проверка входных данных — разные действия. Источник: [Number][js-number].

Для сравнения значений в собственных решениях используйте `===` и `!==`. Строгое равенство не преобразует операнды разных типов к общему типу. Источник: [строгое равенство][js-equality].

```js
console.log(12 === "12");         // false
console.log(12 === Number("12")); // true
```

Строки при сравнении между собой сравниваются как строки, а не как числа. Например, `"12" > "3"` даёт `false`. Логическое преобразование также не интерпретирует текст как команду: `Boolean("false")` даёт `true`, поскольку это непустая строка. Источники: [оператор сравнения][js-greater], [Boolean][js-boolean].

### 4.5. Условия и проверка чисел

`if` позволяет выбрать ветвь выполнения:

```js
const availableHours = 3;
const requiredHours = 5;

if (availableHours >= requiredHours) {
  console.log("Времени достаточно");
} else {
  console.log("Нужно перенести часть работы");
}
```

Несколько проверок можно объединять: `&&` — логическое «И», `||` — логическое «ИЛИ», `!` — логическое отрицание. В заданиях используйте их для объединения условий допустимости данных. Источник: [условия и управление выполнением][js-control].

Для проверки числовых значений пригодятся:

```js
console.log(Number.isFinite(7));     // true
console.log(Number.isFinite(NaN));   // false
console.log(Number.isFinite("7"));   // false
console.log(Number.isInteger(7));    // true
console.log(Number.isInteger(7.5));  // false
console.log(Number.isInteger("7"));  // false
```

`Number.isFinite()` проверяет, является ли значение конечным числом. `Number.isInteger()` проверяет, является ли значение целым числом. Эти методы не преобразуют строку в число. Проверка целочисленности не заменяет проверку диапазона, например запрет отрицательного количества задач. Источники: [Number.isFinite()][js-finite], [Number.isInteger()][js-integer].

В этой работе количество задач ограничено диапазоном `0…1000`: проверяйте тип и целочисленность, а затем границы. Верхнее ограничение — условие учебного задания, а не ограничение JavaScript.

### 4.6. Циклы

Цикл `for` удобен для обхода известного диапазона:

```js
let totalHours = 0;

for (let day = 1; day <= 3; day += 1) {
  totalHours += 2;
  console.log(`День ${day}: накоплено ${totalHours} ч.`);
}
```

Цикл `while` выполняется, пока условие истинно:

```js
let pagesLeft = 7;

while (pagesLeft > 0) {
  pagesLeft -= 1;
}

console.log("Непрочитанных страниц:", pagesLeft);
```

До запуска цикла определите, какое значение приближает программу к завершению. В примере `pagesLeft` уменьшается на каждой итерации. Ошибочное условие или отсутствие изменения могут привести к бесконечному циклу. Источник: [циклы и итерации][js-loops].

Для строкового вывода используем шаблонные строки в обратных кавычках: `${выражение}` подставляет вычисленное значение. Для отображения процента с одним знаком после точки можно использовать `percentage.toFixed(1)`; результат этого метода — строка, предназначенная здесь для вывода. Источники: [шаблонные строки][js-template], [toFixed()][js-fixed].

### Задание 1. Один файл — две среды выполнения

Создайте `practice-01/js/hello.js`:

```js
"use strict";

const studentName = "Учебный студент";
const groupName = "Учебная группа";
const practiceNumber = 1;

console.log(`Студент: ${studentName}`);
console.log(`Группа: ${groupName}`);
console.log(`Практическая работа: ${practiceNumber}`);
console.log("JavaScript успешно запущен");

```

Замените имя и группу своими данными. Строка `"use strict";` включает строгий режим для этого скрипта; в частности, случайное присваивание необъявленной переменной станет ошибкой. Источник: [строгий режим][js-strict].

**Запуск через Node.js.** Из корня репозитория выполните:

```bash
node practice-01/js/hello.js
```

### Задание 3. Сводка выполнения задач

Представьте, что вы готовите расчётную часть будущего приложения управления задачами. Пока приложение получает только общее количество задач и число выполненных задач.

В файле `practice-01/js/progress.js` задайте входные данные:

```js
"use strict";

const totalTasks = 12;
const completedTasks = 5;

// Здесь разместите своё решение.
```

**Правила обработки:**

1. `totalTasks` и `completedTasks` должны быть числами и целыми значениями. Строки автоматически не преобразуются.
2. Допустимо `0 <= totalTasks <= 1000` и `0 <= completedTasks <= totalTasks`.
3. При недопустимых данных выведите одно понятное сообщение, начинающееся с `Ошибка:`. Не выводите после него обычную сводку.
4. Если оба значения равны нулю, выведите `Задач пока нет`. Процент в этом случае не рассчитывается.
5. Для остальных допустимых данных вычислите оставшееся количество задач, процент выполнения и статус.

Статус определяется так:

| Условие | Статус |
|---|---|
| Задачи есть, но ни одна не выполнена | `Не начато` |
| Выполнена часть задач | `В работе` |
| Выполнены все задачи | `Завершено` |

Процент рассчитывайте как `completedTasks / totalTasks * 100`. Для отображения используйте один знак после десятичной точки. Статус определяйте по исходным количествам, а не по округлённому проценту.

**Пример ожидаемого вывода** для `totalTasks = 12`, `completedTasks = 5`:

```text
Всего задач: 12
Выполнено: 5
Осталось: 7
Прогресс: 41.7%
Статус: В работе
```

**Обязательные проверки:**

| `totalTasks` | `completedTasks` | Ожидаемое поведение |
|---:|---:|---|
| `12` | `5` | Осталось 7; прогресс 41.7%; статус «В работе». |
| `0` | `0` | Сообщение «Задач пока нет», без расчёта процента. |
| `5` | `0` | Осталось 5; прогресс 0.0%; статус «Не начато». |
| `5` | `5` | Осталось 0; прогресс 100.0%; статус «Завершено». |
| `5` | `6` | Ошибка: выполнено больше, чем существует. |
| `-1` | `0` | Ошибка: отрицательное количество. |
| `5` | `2.5` | Ошибка: дробное количество. |
| `"5"` | `2` | Ошибка: вместо числа передана строка. |
| `1001` | `0` | Ошибка: превышена верхняя граница. |
| `NaN` | `0` | Ошибка: недопустимое числовое значение. |

Меняйте исходные значения и запускайте файл повторно. Автоматизированный тестовый фреймворк пока не нужен. После проверок верните данные своего варианта и зафиксируйте результаты в отчёте.

### Задание 4. План выполнения задач по дням

В `practice-01/js/plan.js` задайте данные:

```js
"use strict";

const totalTasks = 12;
const completedTasks = 5;
const dailyLimit = 3;

// Здесь разместите своё решение.
```

Нужно определить, за сколько дней будут выполнены **оставшиеся**, а не все исходные задачи. В учебной модели каждый день рабочий, новые задачи не появляются, а за день выполняется не больше `dailyLimit` задач.

**Требования:**

- Проверяйте `totalTasks` и `completedTasks` по правилам задания 3.
- `dailyLimit` должен быть целым числом от `1` до `1000`. Проверка обязательна даже при отсутствии оставшихся задач.
- Для недопустимых данных выведите `Ошибка: ...` и не запускайте цикл.
- Используйте цикл `while`. На каждой итерации увеличивайте номер дня, определяйте количество задач на этот день и уменьшайте остаток.
- За последний день нельзя выполнить больше задач, чем осталось. Для выбора меньшего из двух чисел можно использовать `Math.min()` или условие `if`.
- Если все задачи уже выполнены, выведите сообщение об этом и `Потребуется дней: 0`.

`Math.min(a, b)` возвращает меньшее из двух чисел; см. [справочник MDN][js-min]. Это вспомогательный инструмент, а не обязательное требование к решению.

**Пример ожидаемого вывода** для `12`, `5`, `3`:

```text
Осталось задач: 7
День 1: выполнено 3, осталось 4
День 2: выполнено 3, осталось 1
День 3: выполнено 1, осталось 0
Потребуется дней: 3
```

**Обязательные проверки:**

| `totalTasks` | `completedTasks` | `dailyLimit` | Ожидаемое поведение |
|---:|---:|---:|---|
| `12` | `5` | `3` | 3 дня; в последний день выполнена 1 задача. |
| `10` | `4` | `3` | 2 дня, по 3 задачи в день. |
| `5` | `3` | `10` | 1 день, выполнено только 2 оставшиеся задачи. |
| `5` | `5` | `2` | 0 дней; цикл не выполняется. |
| `0` | `0` | `2` | 0 дней; цикл не выполняется. |
| `5` | `2` | `0` | Ошибка; цикл не запускается. |
| `5` | `2` | `1.5` | Ошибка: дробной дневной нормы быть не должно. |
| `5` | `6` | `2` | Ошибка: некорректное число выполненных задач. |
| `5` | `2` | `"2"` | Ошибка: дневная норма задана строкой. |
| `5` | `2` | `1001` | Ошибка: превышена верхняя граница нормы. |

Не заменяйте весь цикл единственной формулой количества дней: цель задания — получить и проверить пошаговый план. Не используйте массивы и собственные функции в обязательном решении этой ПР.

**Критерий готовности:** остаток не становится отрицательным; последняя итерация корректна; недопустимый ввод не приводит к бесконечному циклу.

### Задание 5. Поиск логических ошибок через DevTools

В файле `practice-01/js/debug.js` разместите программу **с намеренными ошибками**:

const plannedText = "8";

По условиям программы из восьми задач были выполнены три, а затем ещё две. Контрольная сумма должна быть суммой номеров задач **от 1 до 4 включительно**.

На защите студент запускает задания, объясняет выбранные условия и демонстрирует проверку на новых данных. Возможное небольшое изменение: изменить верхнюю границу количества задач, проверить другой дневной лимит или объяснить последнюю итерацию цикла.

Использование справочников и вспомогательных инструментов не заменяет понимание решения. Фрагмент, который студент не может объяснить и изменить, не подтверждает освоение материала.

## 10. Рекомендуемые критерии оценки

Шкала ниже предложена для этой практической работы и не заменяет утверждённую балльно-рейтинговую систему дисциплины.

| Оценка | Основание |
|---|---|
| **0 — не представлено** | Нет доступного результата, который можно проверить. |
| **3 — базовый уровень** | Подготовлено окружение, воспроизведены начальные примеры и показан запуск, но самостоятельные задания, индивидуальный вариант или проверки выполнены не полностью. Студент объясняет представленную часть. |
| **4 — работа выполнена** | Выполнены все обязательные задания и свой вариант; пройдены проверки; оформлен README; показана отладка; студент объясняет код и вносит небольшое изменение на защите. |
| **5 — расширенный уровень** | Выполнены условия оценки 4 и одно содержательное расширение с собственными проверками; студент обосновывает реализацию и успешно защищает работу. |

**Оценка «отлично» выставляется только после защиты.** Декоративная вёрстка, количество строк и установка дополнительных библиотек сами по себе не повышают оценку.

## 11. Частые проблемы

| Проблема | Что проверить |
|---|---|
| `node` или `git` не найдены | Установлен ли инструмент; открыт ли новый терминал после установки. |
| PowerShell блокирует `npm.ps1` | Запустить `npm.cmd --version` или использовать профиль Command Prompt; не отключать защиту системы. |
| Node.js не находит файл | Проверить текущую папку терминала и путь `practice-01/js/имя.js`. |
| Браузер показывает только заголовок | Результат находится в Console, а не в HTML. |
| Изменения не видны | Сохранить файл, проверить путь в `script`, перезагрузить страницу. |
| `Identifier ... has already been declared` | Проверить повторные объявления и подключение нескольких файлов с одинаковыми именами. |
| Вместо суммы получился длинный текст | Проверить типы операндов и необходимость явного преобразования. |
| Нулевые данные дают `NaN` | Проверить деление на ноль и отдельную обработку отсутствия задач. |
| Цикл не заканчивается | Остановить процесс в терминале через `Ctrl+C`; для браузерного кода закрыть зависшую вкладку. Проверить лимит и изменение остатка до повторного запуска. |
| `remote origin already exists` | Посмотреть `git remote -v`, а не повторять добавление удалённого репозитория. |
| GitHub отклоняет отправку | Проверить адрес, права и наличие другой истории; не использовать принудительную отправку как универсальное решение. |

Описание объявления переменных, числовых преобразований, циклов и Git-команд приведено в источниках ниже.
