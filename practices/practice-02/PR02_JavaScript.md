## 1. Цель и результаты работы

**Цель работы** — выделить логику небольшого приложения в функции и ES-модули, организовать данные в виде массива объектов и проверить операции без пользовательского интерфейса.

В ходе работы необходимо освоить:

- объявление и вызов функций, параметры, возвращаемые значения и стрелочные функции;
- создание объектов, чтение свойств, деструктуризацию и поверхностное копирование;
- поиск, отбор и преобразование элементов массива с помощью `find`, `filter` и `map`;
- изменение данных без изменения переданного массива и его объектов;
- разделение данных, прикладной логики и демонстрационного сценария через `import` и `export`.

**Итоговый результат:** девять функций для создания задачи, чтения списка, расчёта сводки, добавления, изменения и удаления записей; общий и индивидуальный сценарии; проверяемый отчёт в Markdown.

## 4. Теоретические сведения

### 4.1. Функция: входные данные и результат

Функция объединяет действия под одним именем. Параметры задаются в объявлении, аргументы передаются при вызове. `return` завершает выполнение функции и передаёт значение вызывающему коду. Без возвращаемого значения результатом вызова будет `undefined`. Подробнее: [функции JavaScript][js-functions].

```js
function calculateArea(width, height) {
  const area = width * height;
  return area;
}

const firstArea = calculateArea(4, 6);
const secondArea = calculateArea(3, 5);

console.log(firstArea);  // 24
console.log(secondArea); // 15
```

`width` и `height` — параметры. Числа `4` и `6` — аргументы первого вызова. Переменная `area` объявлена внутри функции и недоступна снаружи этой функции.

**Возврат и вывод — разные действия.** В рамках работы расчётная функция возвращает данные, а демонстрационный сценарий решает, как их показать. Такой код можно будет вызывать и из обработчика события на странице.

```js
function calculateCost(price, quantity) {
  return price * quantity;
}

const cost = calculateCost(120, 3);
console.log(`Стоимость: ${cost}`);
```

Добавление `console.log()` внутрь функции не заменяет `return`. Если следующая операция ожидает число или объект, ей необходимо получить это значение, а не только увидеть сообщение в терминале.

### 4.2. Стрелочные функции и параметры по умолчанию

Для небольших функций удобно использовать стрелочную запись:

```js
const double = (value) => value * 2;

const doubleWithBlock = (value) => {
  return value * 2;
};

console.log(double(6));          // 12
console.log(doubleWithBlock(6)); // 12
```

При краткой записи результат выражения возвращается автоматически. При теле в фигурных скобках для возврата значения нужен `return`. Для краткого возврата объекта его литерал помещается в круглые скобки:

```js
const makePoint = (x, y) => ({ x, y });
console.log(makePoint(2, 5)); // { x: 2, y: 5 }
```

В этой работе стрелочные функции прежде всего используются как аргументы методов массивов. Особенности `this` и использование функций как конструкторов в обязательную часть не входят. Источник: [стрелочные функции][js-arrow].

Параметр по умолчанию применяется, если аргумент не передан или равен `undefined`. Значения `null`, `0` и пустая строка сами по себе его не включают. Источник: [параметры по умолчанию][js-defaults].

```js
function makeCaption(text = "Без названия") {
  return text;
}

console.log(makeCaption());          // Без названия
console.log(makeCaption(undefined)); // Без названия
console.log(makeCaption(null));      // null
```

Значение по умолчанию не заменяет валидацию. Например, обязательный строковый аргумент, получивший `null`, необходимо проверить отдельно.

### 4.3. Объекты и деструктуризация

Объект объединяет связанные значения в свойства:

```js
const book = {
  id: 12,
  title: "Основы веб-разработки",
  available: true,
};

console.log(book.title);
console.log(book["available"]);
```

Для известного имени свойства обычно используется точка. Квадратные скобки позволяют обратиться к свойству, имя которого хранится в переменной. Отсутствующее свойство обычного объекта при чтении даёт `undefined`. Источник: [работа с объектами][js-objects].

Деструктуризация извлекает свойства в отдельные переменные:

```js
const { id, title } = book;
console.log(id, title);
```

Это не копирование всего объекта и не удаление свойств из него. Если извлекаемое свойство само содержит объект, независимая глубокая копия при этом не создаётся. Подробнее: [деструктуризация][js-destructuring].

В решении необходимо использовать деструктуризацию хотя бы в одном осмысленном месте, например при выводе сводки в `main.js`. Применение синтаксиса ради формального наличия без понятного назначения не требуется.

### 4.4. Объект, ссылка на него и `const`

Присваивание объекта другой переменной не создаёт независимую копию:

```js
const original = { title: "Черновик", published: false };
const alias = original;

alias.published = true;

console.log(original.published); // true
console.log(original === alias); // true
```

Обе переменные указывают на один объект. `const` запрещает переприсваивание переменной, но не делает свойства объекта неизменяемыми. Объекты сравниваются по идентичности: два отдельно созданных объекта с одинаковыми полями не становятся равными при `===`. Источник: [объекты и сравнение][js-objects].

Аргументы функций передаются по значению. Для объекта передаваемое значение позволяет обратиться к тому же объекту; поэтому изменение его свойства внутри функции заметно снаружи. Это не означает, что присваивание нового объекта самому параметру заменит переменную вызывающего кода. Источник: [передача аргументов функции][js-functions].

```js
function markPublished(article) {
  article.published = true;
}

const article = { title: "Черновик", published: false };
markPublished(article);
console.log(article.published); // true
```

В обязательных функциях ПР2 такой способ изменения входных объектов не используется.

### 4.5. Массив объектов и идентификатор записи

Массив хранит последовательность элементов. В этой работе каждый элемент — объект задачи, без пропущенных позиций. Первый индекс равен `0`, а `length` показывает длину массива. Источник: [Array][js-array].

```js
const books = [
  { id: 12, title: "JavaScript" },
  { id: 35, title: "HTTP" },
];

console.log(books.length); // 2
console.log(books[0].id);  // 12
```

**Индекс и `id` имеют разное назначение.** Индекс показывает текущее место в массиве. `id` идентифицирует запись и в модели этой работы не меняется после удаления соседнего элемента. Поиск задачи по `id` нельзя заменять обращением `tasks[id]`.

Для простого последовательного обхода подходит `for...of`:

```js
for (const book of books) {
  console.log(book.title);
}
```

В прикладных функциях вывод не выполняется: цикл может использоваться, например, для накопления счётчика.

### 4.6. `find`, `filter`, `map` и функция обратного вызова

Функция обратного вызова, или callback, передаётся другой функции. В приведённых методах массива она вызывается при обработке элементов; асинхронность для этого не требуется.

| Метод | Назначение в этой работе | Результат |
|---|---|---|
| `find` | Найти первую запись, удовлетворяющую условию. | Найденный элемент или `undefined`. |
| `filter` | Отобрать все подходящие записи. | Новый массив, в том числе пустой. |
| `map` | Преобразовать каждый элемент. | Новый массив результатов преобразования. |

```js
const products = [
  { id: 12, name: "Папка", price: 90 },
  { id: 35, name: "Блокнот", price: 240 },
  { id: 48, name: "Ручка", price: 60 },
];

const selected = products.find((product) => product.id === 35);
const inexpensive = products.filter((product) => product.price < 100);
const names = products.map((product) => product.name);

console.log(selected.name); // Блокнот
console.log(inexpensive.length); // 2
console.log(names); // ["Папка", "Блокнот", "Ручка"]
```

Источники: [`find`][js-find], [`filter`][js-filter], [`map`][js-map].

Если совпадения нет, перед чтением свойства результата `find` необходима проверка:

```js
const missing = products.find((product) => product.id === 999);

if (missing === undefined) {
  console.log("Запись не найдена");
} else {
  console.log(missing.name);
}
```

`map` создаёт новый массив, но не гарантирует отсутствие изменений исходных объектов внутри callback. Код `product.price = 100` всё равно изменит объект, даже если записан внутри `map`. `filter` также не делает независимые копии отобранных объектов. В решении callback-функции не должны менять переданные записи.

### 4.7. Spread и поверхностное копирование

Spread-синтаксис `...` позволяет перенести элементы массива или собственные перечисляемые свойства объекта в новую структуру:

```js
const oldNumbers = [2, 4];
const newNumbers = [...oldNumbers, 6];

const oldBook = { id: 12, title: "Черновик", available: false };
const newBook = { ...oldBook, available: true };

console.log(oldNumbers);       // [2, 4]
console.log(newNumbers);       // [2, 4, 6]
console.log(oldBook.available); // false
console.log(newBook.available); // true
```

Копирование поверхностное: вложенные объекты автоматически не копируются. В `const copy = [...items]` создаётся новый массив, но ссылки на объекты внутри него сохраняются. При изменении одной записи нужен новый массив **и новый объект изменяемой записи**. Неизменённые объекты разрешается использовать повторно, не изменяя их свойства. Источник: [spread-синтаксис][js-spread].

Порядок свойств имеет значение: при повторении имени последнее значение перекрывает предыдущее. Поэтому `{ ...oldBook, available: true }` и `{ available: true, ...oldBook }` могут дать разные результаты.

Модель ПР2 намеренно плоская: все поля задачи содержат примитивные значения. Универсальная библиотека глубокого копирования здесь не нужна.

### 4.8. Контракт функции и ожидаемые ошибки

**Контракт** в этой методичке — точное описание аргументов, результата и поведения при ошибке. Это позволяет проверять функции независимо от способа их реализации.

Для создания и изменения данных используется объект результата. Пример на отдельной задаче нормализации подписи:

```js
function normalizeCaption(value) {
  if (typeof value !== "string") {
    return { ok: false, error: "Подпись должна быть строкой" };
  }

  const caption = value.trim();
  if (caption.length === 0) {
    return { ok: false, error: "Подпись не должна быть пустой" };
  }

  return { ok: true, caption };
}

const result = normalizeCaption("  Раздел 1  ");

if (result.ok) {
  console.log(result.caption);
} else {
  console.error(`Ошибка: ${result.error}`);
}
```

`trim()` возвращает строку без пробельных символов по краям. Метод необходимо вызывать после проверки типа. Источник: [`String.prototype.trim()`][js-trim].

В ПР2 объект результата — выбранное соглашение, а не обязательное правило JavaScript. Для ожидаемых ошибок, перечисленных в задании, необходимо возвращать `{ ok: false, error: "Понятное сообщение" }`, а не завершать программу необработанным исключением. Точная формулировка сообщения свободная, но причина отказа должна быть понятна.

Для чтения используются более простые результаты: объект задачи, массив или объект сводки. Отсутствие записи при поиске обозначается `undefined`, а не объектом ошибки. Конкретные контракты перечислены в разделе 6.

### 4.9. ES-модули и разделение ответственности

`export` делает объявление доступным другим модулям, а `import` подключает его по имени:

```js
// geometry.js
export function rectangleArea(width, height) {
  return width * height;
}
```

```js
// demo.js
import { rectangleArea } from "./geometry.js";

console.log(rectangleArea(3, 7)); // 21
```

Каждый блок относится к отдельному файлу. Относительный путь вычисляется от импортирующего файла; в примерах курса расширение `.js` указывается явно. Модули имеют собственную область видимости и выполняются в строгом режиме. Источник: [JavaScript modules][js-modules].

В Node.js для файлов `.js` внутри ПР2 явно задаётся `"type": "module"` в ближайшем родительском `package.json`. Это позволяет последовательно использовать `import` и `export`, не смешивая их с `require` и `module.exports`. Источник: [поле `type` в Node.js][node-packages].

В этой работе код запускается через Node.js. Простое открытие HTML как `file://`, использованное в ПР1, не является инструкцией запуска модульного проекта. Подключение модулей на странице и локальный веб-сервер будут рассмотрены в работе с браузером. Ограничения загрузки браузерных модулей описаны в [MDN][js-modules].

### 6.2. Задание 2. Модель данных и создание задачи

Модель задачи фиксируется для всех обязательных заданий:

```js
{
  id: 20,
  title: "Подготовить демонстрацию",
  completed: false,
  priority: "medium"
}
```

| Поле | Правило |
|---|---|
| `id` | Число, положительное безопасное целое: `Number.isSafeInteger(id)` и `id > 0`. В пределах списка идентификаторы уникальны. |
| `title` | Строка. После `trim()` длина от 1 до 100 включительно. В объект записывается очищенная строка. Внутренние пробелы сохраняются. |
| `completed` | Логическое значение. При создании новой задачи всегда `false`. |
| `priority` | Строго одно из значений: `"low"`, `"medium"`, `"high"`. По умолчанию — `"medium"`. |

Длина названия в рамках задания определяется через `.length`. Для JavaScript-строк это количество кодовых единиц UTF-16, а не универсальный подсчёт видимых символов. Работа с графемами и эмодзи не требуется. Источники: [`Number.isSafeInteger()`][js-safe-integer], [`String.length`][js-string-length].

Необходимо реализовать экспортируемую функцию:

```js
export function createTask(id, title, priority = "medium") {
  // Проверка аргументов и создание объекта результата.
}
```

**Результат при успехе:**

```js
{
  ok: true,
  task: {
    id: 20,
    title: "Подготовить демонстрацию",
    completed: false,
    priority: "medium"
  }
}
```

**Результат при ошибке:**

```js
{ ok: false, error: "Понятное описание причины" }
```

Сначала проверяются типы, затем ограничения. Строковый идентификатор не преобразуется в число, `null` не заменяется значением по умолчанию. При нескольких ошибках достаточно вернуть сообщение об одной из них; порядок проверок не фиксируется.

Каждый успешный вызов создаёт новый объект задачи. Проверка уникальности `id` здесь невозможна: функция ещё не получает список. Она будет выполнена в `addTask`.

**Обязательные проверки:**

| Вызов или входные данные | Ожидаемое поведение |
|---|---|
| `createTask(20, "Новая задача", "high")` | Успех; заданные поля, `completed: false`. |
| Приоритет не передан или передан `undefined` | Приоритет `"medium"`. |
| Название `"  Проверить  данные  "` | Название `"Проверить  данные"`. |
| Название длиной 1 и длиной 100 | Успех. |
| Пустая строка, пробелы, длина 101 | `ok: false`. |
| Название `42`, `null`, `undefined` | `ok: false`, без ошибки вызова `trim`. |
| `id`: `0`, `-1`, `1.5`, `"4"`, `NaN`, `Infinity`, `null`, `undefined` | `ok: false`. |
| `id`: `Number.MAX_SAFE_INTEGER` | Успех. |
| `id`: `Number.MAX_SAFE_INTEGER + 1` | `ok: false`. |
| Приоритет `"urgent"`, `"HIGH"`, `" high "`, `null`, `1` | `ok: false`. |
| Два вызова с одинаковыми корректными аргументами | Равные поля, но разные объекты задач. |

**Критерий готовности:** создание и нормализация работают по контракту; ожидаемые ошибки возвращаются как данные, а не обрывают программу.

### 6.3. Задание 3. Чтение списка и расчёт сводки

Общий набор `demoTasks` размещается в `src/data.js` и не подменяется данными своего варианта:

```js
export const demoTasks = [
  { id: 1, title: "Изучить функции", completed: true, priority: "medium" },
  { id: 4, title: "Подготовить модель задач", completed: false, priority: "high" },
  { id: 7, title: "Проверить методы массивов", completed: false, priority: "low" },
  { id: 10, title: "Оформить README", completed: true, priority: "medium" },
];
```

Необходимо реализовать четыре функции в `task-service.js`:

| Функция | Результат | Требование к реализации |
|---|---|---|
| `findTaskById(tasks, id)` | Первый объект с указанным `id` или `undefined`. | Использовать `find` и строгое сравнение. Возвращается найденный объект, а не его копия. |
| `getPendingTasks(tasks)` | Новый массив задач с `completed === false`. | Использовать `filter`. Порядок исходных записей сохраняется. |
| `getTaskTitles(tasks)` | Новый массив строк с названиями всех задач. | Использовать `map`. Порядок сохраняется. |
| `getTaskStats(tasks)` | Объект `{ total, completed, pending, progress }`. | Считать данные по переданному массиву. Разрешены цикл или методы массива. |

Для `getTaskStats` устанавливаются правила:

```text
total     = количество задач
completed = количество задач с completed === true
pending   = total - completed
progress  = completed / total * 100, если total > 0
progress  = 0, если total === 0
```

Все четыре поля — числа. `progress` возвращается **без предварительного округления**. В `main.js` для отображения используется `progress.toFixed(1)`; для пустого списка выводится «Задач пока нет», а не строка с процентом. Нулевое поле `progress` в сводке для пустого списка — выбранное соглашение этой модели. Метод [`toFixed()`][js-fixed] возвращает строку, поэтому он применяется при отображении, а не внутри расчёта.

Общий набор даёт:

```js
{ total: 4, completed: 2, pending: 2, progress: 50 }
```

**Граница обязательного контракта:** аргумент `tasks` во всех функциях этой работы — корректный обычный массив задач без пропусков и с уникальными `id`. Проверять заново каждое поле всех существующих записей при каждом чтении не требуется. Обработка `tasks = null`, разреженных массивов, циклических структур и произвольных посторонних объектов не входит в обязательный минимум. Корректность новых данных обеспечивается функциями создания и изменения.

Для поиска строка `"4"` не совпадает с числом `4`: результатом будет `undefined`. Остальные чтения получают только массив, поэтому отдельного объекта ошибки для них не предусмотрено.

**Обязательные проверки:**

| Проверка | Ожидаемый результат |
|---|---|
| Поиск `id = 4` в общем наборе | Вторая запись с `id = 4`, не элемент с индексом 4. |
| Поиск `id = 777`, строкового `"4"` или поиск в `[]` | `undefined`. |
| Невыполненные задачи общего набора | Идентификаторы `[4, 7]` в этом порядке. |
| Отбор из `[]` или списка, где всё выполнено | Новый пустой массив. |
| Отбор из списка, где ничего не выполнено | Новый массив со всеми исходными записями. |
| Названия общего набора | Четыре названия в исходном порядке. |
| Названия пустого списка | `[]`. |
| Сводка общего набора | `{ total: 4, completed: 2, pending: 2, progress: 50 }`. |
| Сводка `[]` | Все поля равны `0`. |
| Четыре задачи, ни одна не выполнена / выполнены все | Прогресс `0` / `100`. |
| Три задачи, выполнена одна | Числовой прогресс около `33.3333333333`; отображение `33.3%`. |

Исходный массив и свойства задач после чтения сохраняются. Полученный через `findTaskById` объект не используется для прямого изменения: для этого предусмотрены функции задания 4.

**Критерий готовности:** функции работают на любом корректном массиве в рамках модели, а не только на `demoTasks`; результаты чтения и сводки соответствуют контрактам.

### 6.4. Задание 4. Добавление, изменение и удаление

Необходимо реализовать четыре функции:

```js
export function addTask(tasks, id, title, priority = "medium") {
  // Добавление задачи в конец нового массива.
}

export function setTaskCompleted(tasks, id, completed) {
  // Изменение признака выполнения выбранной задачи.
}

export function renameTask(tasks, id, title) {
  // Изменение названия выбранной задачи.
}

export function removeTask(tasks, id) {
  // Удаление задачи по идентификатору.
}
```

**Общий формат успешного результата:**

```text
{ ok: true, tasks: <новый массив задач> }
```

**Общий формат отказа:**

```js
{ ok: false, error: "Понятное описание причины" }
```

Во всех четырёх операциях проверяется корректность переданного `id` по тем же правилам, что и при создании. Приведение типов не выполняется.

| Операция | Правила |
|---|---|
| `addTask` | Создать запись через `createTask`. Отклонить добавление, если такой `id` уже присутствует. При успехе добавить задачу в конец нового массива. |
| `setTaskCompleted` | Принять только `true` или `false`. При отсутствии задачи вернуть ошибку. Изменить только `completed`. |
| `renameTask` | Проверить и нормализовать название по правилам `createTask`. При отсутствии задачи вернуть ошибку. Изменить только `title`; остальные поля сохранить. |
| `removeTask` | При отсутствии задачи вернуть ошибку. При успехе вернуть массив без выбранной записи, сохранив порядок остальных. |

Для исключения повторяющегося кода можно выделить небольшие внутренние функции проверки `id` и названия. Публичные имена и форматы результатов при этом сохраняются.

**Требования к изменению данных:**

1. Переданные массивы и объекты не изменяются — ни при успехе, ни при ошибке.
2. Успешная операция возвращает новый массив.
3. При переименовании и изменении статуса создаётся новый объект выбранной задачи. Неизменённые записи разрешается использовать повторно.
4. Для единообразия повторная установка уже имеющегося статуса или названия тоже считается успешной и возвращает новый массив и новый объект выбранной задачи.
5. Порядок элементов сохраняется. Удаление не меняет идентификаторы остальных записей.
6. В модуле нет глобального изменяемого списка. Каждая функция работает с переданным `tasks`.

Для добавления необходимо использовать spread массива, для обновления — `map` и spread объекта, для удаления — `filter`. Эти ограничения нужны для отработки изучаемых операций, а не потому, что других способов реализации не существует.

Вызовы `push`, `splice` и прямые присваивания свойствам **входных** объектов не подходят под контракт этой работы. Изменение нового объекта, созданного внутри функции, само по себе не является изменением входных данных.

**Обязательные проверки:**

| Проверка | Ожидаемое поведение |
|---|---|
| Добавить в общий набор корректную задачу с `id = 20` | Пять записей; новая запись в конце; исходный список содержит четыре записи. |
| Добавить корректную задачу в `[]` | Новый массив из одной записи; исходный массив пуст. |
| Добавить задачу с существующим `id = 4` | Ошибка; исходный список сохранён. |
| Добавить задачу с некорректным полем | Ошибка по тем же правилам, что в задании 2. |
| Изменить `completed` для `id = 4` на `true`, затем обратно на `false` | Меняется только признак выполнения; предыдущие состояния сохранены. |
| Передать вместо `completed` строку, число, `null`, `undefined` | Ошибка. Значения `"false"` и `0` не преобразуются в логические. |
| Переименовать `id = 10`, передав краевые пробелы | В новом объекте очищенное название; `id`, `completed` и `priority` сохранены. |
| Переименовать с некорректным названием | Ошибка; исходная запись сохранена. |
| Переименовать или изменить статус отсутствующей задачи | Ошибка. |
| Передать некорректный `id` в любую операцию | Ошибка, без преобразования строки в число. |
| Повторно установить текущее название или статус | Успех; новый массив и новый объект выбранной записи. |
| Удалить `id = 7` из общего набора | Идентификаторы `[1, 4, 10]`; исходный набор сохранён. |
| Удалить единственную задачу | Успех; новый пустой массив. |
| Удалить отсутствующую задачу или удалить из `[]` | Ошибка. |

**Как проверить отсутствие мутации.** До вызова необходимо сохранить исходные значения полей. После вызова — сравнить входной массив и его объекты с этими значениями. Для успешного обновления дополнительно проверяются разные ссылки на массив и на изменённую запись. Одного условия `result.tasks !== originalTasks` недостаточно: массив может быть новым, а объект внутри — уже испорченным.

**Критерий готовности:** четыре операции соблюдают форматы результатов, отклоняют некорректные аргументы и не изменяют входные данные.

Пример **использования** функции, не её реализации:

```js
let currentTasks = demoTasks;

const result = addTask(currentTasks, 20, "Добавить проверку", "high");

if (result.ok) {
  currentTasks = result.tasks;
} else {
  console.error(`Ошибка: ${result.error}`);
}

const { total, completed, pending, progress } = getTaskStats(currentTasks);

console.log(`Всего: ${total}; выполнено: ${completed}; осталось: ${pending}`);
if (total === 0) {
  console.log("Задач пока нет");
} else {
  console.log(`Прогресс: ${progress.toFixed(1)}%`);
}
```

Остальные действия необходимо добавить самостоятельно. Для последовательных результатов можно использовать разные имена либо небольшую вспомогательную функцию в `main.js`. Прикладная логика остаётся в `task-service.js`.

**Контрольная последовательность:**

| Этап | Всего | Выполнено | Осталось | Отображение прогресса |
|---|---:|---:|---:|---|
| Исходный набор | 4 | 2 | 2 | `50.0%` |
| После добавления `id = 20` | 5 | 2 | 3 | `40.0%` |
| После выполнения `id = 4` | 5 | 3 | 2 | `60.0%` |
| После переименования `id = 10` | 5 | 3 | 2 | `60.0%` |
| После удаления `id = 7` | 4 | 3 | 1 | `75.0%` |

Идентификаторы итогового массива: `[1, 4, 10, 20]`. Единственная невыполненная задача имеет `id = 20`. Это **ожидаемые**, а не заранее полученные результаты конкретного решения.

#### Готовый проверочный сценарий

Из корня личного репозитория:

```bash
node practice-02/checks.js
```

Из папки `practice-02`:

```bash
npm run check
```

В комплекте подготовлено **35 именованных проверочных сценариев**. Некоторые сценарии последовательно проверяют несколько недопустимых значений. Поэтому число 35 относится к группам проверок в выводе, а не к количеству всех вызовов функций.

Файл использует встроенный модуль Node.js `node:assert/strict`: он сравнивает полученные значения с ожидаемыми. Дополнительная библиотека и отдельный тестовый фреймворк не нужны. Разработка тестовой инфраструктуры в этой работе не требуется. Источник: [Node.js Assert][node-assert].

`OK` выводится только после успешного сравнения. При ошибке выводятся `FAIL`, название сценария и сообщение; процесс завершается с ненулевым кодом. Проверки не охватывают оформление, объяснение решения, обязательное использование методов массива и индивидуальный вариант — эти части проверяются отдельно.

В готовом файле нельзя удалять неудобные проверки или заменять вызовы функций заранее записанными результатами. Допускается дополнять его своими случаями. При самостоятельном создании структуры вместо готового сценария допустимо выполнить все проверки из таблиц вручную и зафиксировать фактические результаты; объём обязательных проверок от этого не уменьшается.

#### Собственные проверки

К общим проверкам необходимо добавить **не менее трёх собственных случаев**, отличающихся исходными данными или последовательностью действий. Например: добавление после удаления, изменение первой и последней записи, последовательное обновление нескольких задач. Для каждого случая сначала задаётся ожидаемый результат, затем фиксируется фактический.

Пустой список и неверные типы уже входят в обязательную проверку; простого переименования существующих тестов для собственных случаев недостаточно.

**Критерий готовности:** общий сценарий работает, обработанный отказ не повреждает состояние, общие и собственные проверки воспроизводятся указанными командами.

## 7. Индивидуальные варианты

Сохраняется номер варианта из ПР1. Если номер ещё не назначен, используется положительный порядковый номер `N` в журнале:

```text
variant = ((N - 1) % 8) + 1
```

При отсутствии номера вариант определяется преподавателем. Вариант задаёт демонстрационные данные, но **не меняет контракты функций и не отменяет общий набор проверок**.

В `data.js` необходимо заполнить `variantNumber` и `variantTasks`. В `variantTasks` размещаются шесть задач с идентификаторами **`11`, `23`, `37`, `41`, `58`, `64`**, в указанном порядке. Названия формулируются самостоятельно по теме варианта. Приоритеты выбираются так, чтобы в исходном наборе присутствовали `low`, `medium` и `high`.

Для однозначной проверки исходного состояния завершёнными отмечаются **первые K задач** в массиве, где K указано в таблице. У остальных `completed: false`.

| Вариант | Тематика шести задач | K: выполнено изначально | Приоритет новой задачи `id = 80` | Начальный прогресс для отображения |
|---:|---|---:|---|---|
| 1 | Подготовка учебного проекта | 0 | `high` | `0.0%` |
| 2 | Подготовка выступления | 1 | `medium` | `16.7%` |
| 3 | Создание сайта-портфолио | 2 | `low` | `33.3%` |
| 4 | Подготовка семинара | 3 | `high` | `50.0%` |
| 5 | Разработка командного прототипа | 4 | `medium` | `66.7%` |
| 6 | Проверка пользовательского интерфейса | 5 | `low` | `83.3%` |
| 7 | Подготовка учебного релиза | 6 | `high` | `100.0%` |
| 8 | Оформление технической документации | 3 | `low` | `50.0%` |

Для своего набора необходимо выполнить **отдельный** сценарий в `main.js`:

1. Вывести исходные данные и сводку.
2. Добавить задачу `id = 80` с собственным названием и приоритетом из таблицы.
3. Установить `completed = true` для `id = 11`. Если задача уже выполнена, операция всё равно проверяется по контракту.
4. Переименовать `id = 23`, сохранив другие поля.
5. Удалить `id = 37`.
6. Попробовать повторно добавить `id = 80` и показать отказ без изменения списка.
7. Зафиксировать итоговые задачи и сводку, отдельно подтвердить сохранность `variantTasks`.

Ожидания промежуточных состояний рассчитываются до запуска и записываются в отчёт. Общий сценарий и вариант должны запускаться одной командой, без ручной замены `demoTasks` и исходных значений между запусками.

Тема варианта не превращает работу в другую систему: во всех вариантах моделируются именно задачи с четырьмя установленными полями.

## 8. Дополнительное задание

После обязательной части можно выполнить одно содержательное расширение. Оно размещается в отдельном модуле `src/task-extra.js`, импортируется в `main.js` и не меняет контракты девяти обязательных функций.

### Вариант А. Поиск задач по части названия

Реализовать `searchTasks(tasks, query)`, возвращающую новый массив подходящих задач. В рамках расширения `tasks` — корректный массив модели, `query` — строка.

Правила: удалить пробелы по краям запроса, искать вхождение без учёта регистра, сохранять порядок. Пустой или пробельный запрос возвращает новый массив всех задач. Исходные записи не меняются. Регулярные выражения и нечёткий поиск не требуются.

Подходящие операции: [`toLowerCase()`][js-lowercase] и [`includes()`][js-includes]. Для `demoTasks` запрос `" ФУНК "` соответствует задаче `id = 1`, а запрос `"несуществующий фрагмент"` — пустому результату.

Необходимо проверить обычный запрос, разный регистр, краевые пробелы, отсутствие совпадений, пустой запрос и пустой список, а также подтвердить неизменность данных.

### Вариант Б. Сводка по приоритетам

Реализовать `getPrioritySummary(tasks)`, возвращающую объект вида:

```js
{
  low: { total: 0, pending: 0 },
  medium: { total: 0, pending: 0 },
  high: { total: 0, pending: 0 }
}
```

Для каждого приоритета рассчитываются общее количество и количество невыполненных задач. Все три приоритета присутствуют в результате, даже если соответствующих задач нет. Исходный массив и его объекты сохраняются.

Для `demoTasks` ожидаются: `low` — всего 1, осталось 1; `medium` — всего 2, осталось 0; `high` — всего 1, осталось 1.

Необходимо проверить смешанный набор, пустой список и список с одним приоритетом. Для реализации достаточно цикла или изученных методов массива; `reduce` не обязателен.

Для выбранного расширения в отчёт включаются описание контракта и собственные проверки. Добавление библиотеки, оформление консольного вывода или переименование файлов сами по себе расширением не считаются.

## 11. Частые проблемы

| Проблема | Что проверить |
|---|---|
| `Cannot use import statement outside a module` | Наличие корректного `practice-02/package.json` с `"type": "module"` и фактическое расположение файла. |
| `ERR_MODULE_NOT_FOUND` | Путь от импортирующего файла, расширение `.js`, написание имени и регистр букв. |
| `does not provide an export named ...` | Совпадение имени в `export` и `import`. |
| `require is not defined` | Отсутствие смешивания CommonJS и ES-модулей. В ПР2 используются `import` и `export`. |
| `npm` не находит `package.json` | Текущую папку. npm-команды выполняются из `practice-02`; команды `node practice-02/...` — из корня репозитория. |
| PowerShell блокирует `npm.ps1` | Возможность запуска `npm.cmd` либо прямого `node`. |
| Функция возвращает `undefined` | Наличие `return`, особенно в стрелочной функции с фигурными скобками. |
| Поиск возвращает не ту запись | Отличие `id` от индекса и использование строгого сравнения. |
| После изменения новой версии изменилась старая | Копирование объекта изменяемой записи, а не только массива. |
| При переименовании сбросились статус и приоритет | Сохранение остальных полей выбранной записи. |
| Новый статус перекрывается старым | Порядок spread и явно заданного свойства. |
| Пустой список даёт `NaN` | Отдельную ветвь для `total === 0`. |
| `trim is not a function` | Проверку типа названия до вызова метода. |
| Все сценарии сообщают «Не реализовано» | Заглушки в `task-service.js`: требуется реализация, а не изменение проверок. |
| После отказа текущее состояние стало `undefined` | Присваивание `currentTasks = result.tasks` только при `result.ok === true`. |

Правила функций, модулей и копирования приведены в разделе 4 и источниках ниже. Для конкретной ошибки полезно отдельно проверить минимальный вызов, а затем вернуться к полному сценарию.
